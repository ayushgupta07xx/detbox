# ADR-009: Publishing conformance rates without a service and without a hand-maintained number

**Date:** 2026-08-09 · **Status:** accepted (2026-08-09)

## Context

ADR-008 settled what a conformance rate *means* and how it ratchets. It did not
say where the number gets **published**, and §4.1 **P4** asks for exactly that:
pass rates published *"including honest failure lists."*

Until now they were published nowhere. The rates existed in two places: an
`--nocapture` line in a CI log that GitHub deletes on a retention schedule, and
`thresholds.tsv`, which records what we *claim* rather than what we *measured*.
The failure list was worse — the console printed `... and 62 more`, so 62 of
konflux's 77 YAML conformance failures had never been written down anywhere at
all. A proof obligation whose evidence expires is not discharged.

The problem this creates is specific: a published number needs a source, and
every obvious source is one we control. A figure typed into a README is a figure
that drifts the first time the parser improves, and nothing notices.

## Options

- **A — A hosted badge endpoint.** Publish a shields.io endpoint JSON to GitHub
  Pages from CI. Live and pretty; needs hosting we do not have, puts the number
  behind a service outage, and the repository stops being self-contained.
- **B — Hand-maintained numbers in the README.** Zero machinery. It is a claim
  nothing re-derives, which is the exact failure mode the fuzz-hours ledger was
  designed to avoid (PR #4), and it would be wrong within one PR of any parser
  change.
- **C — A generated file, regenerated and byte-compared in CI.** The report is
  committed so it is readable at the commit it describes and diffable in review;
  `gate/conformance` regenerates it from the pinned suites and compares bytes,
  so it cannot drift in either direction. Costs a regeneration step in any PR
  that changes what the parser accepts.

## Decision

**C.** `conformance/REPORT.md` is generated by `cargo xtask conformance-report
--write` and byte-compared by `gate/conformance`.

The reason C works here and a committed fuzz-hours ledger did not is worth
stating, because the two look alike and are not. Fuzz hours are a fact about
*runs that happened* — unreproducible, so a file we maintain about ourselves is
the only record and therefore worthless as evidence. A conformance rate is a
pure function of two pinned commits and our own source, so anyone can recompute
it and CI does, every time. **Committing a derived value is safe exactly when
the derivation is reproducible**, and here it is.

That gives a clean division of labour between the two files, and neither is
redundant:

| File | What it is | How it is protected |
|---|---|---|
| `thresholds.tsv` | the claim we make | ratchets one way; `golden-guard`; lowering needs sign-off |
| `REPORT.md` | the measurement | regenerated and byte-compared every CI run |

`REPORT.md` is deliberately **not** added to `golden-guard`. Guarding it would
demand a `[NEEDS-AYUSH-APPROVAL]` header on every PR that improves the parser,
which trains everyone to write that header — the same "gate that cries wolf"
failure the determinism false positive taught us (MILESTONES §0.2). The
regeneration check is the stronger protection anyway: golden-guard asks a human
whether a change was intended, while the byte-compare knows.

**The failure list is complete, and the console list is not.** Truncating at 15
is right for a terminal and wrong for evidence, so `Report::failure_list` now
says where the full list lives instead of just how many it hid. Each entry
carries the suite's own description, so the list reads as *"wrong indentation in
a mapping"* rather than as 77 four-character IDs — which is what makes it
reviewable, and which incidentally corroborates the M2 claim: nearly every
remaining failure is a block/flow context case.

**Badge values are generated; badges are not.** The report emits each badge's
label and message so the number on a badge can only ever be the number measured.
It does not emit the badge image: colour and form are visual design, which is
Ayush's alone (§16), and they land with the launch README (§12).

## Consequences

- **A parser change now has a fourth step**: fetch, regenerate, review the diff,
  commit. CI names the command when it catches you.
- **The diff is the review surface.** One case per line, unpadded, so fixing one
  case deletes exactly one line rather than reflowing the block. When the YAML
  reject rate rises at M2 the diff will show precisely which 60 cases moved.
- **A moved pin is visible.** The pin is read from the fetch receipt into the
  report, so re-pinning a suite changes the published bytes and shows up in
  review rather than silently restating a rate about a different suite.
- **We are betting that reproducibility is enough.** If a future suite is ever
  fetched non-deterministically, the byte-compare becomes a flake, and the fix
  is to pin harder — never to relax the compare.
- **P4 is still not complete**, and this ADR does not complete it: §4.1 names
  toml-test as the third suite and `toml` does not exist until Phase 2.

## Proof impact

Discharges the publication half of konflux **P4** and arms `gate/conformance`
per ADR-003's schedule. Touches no invariant: K1, K2 and K3 are unaffected, and
`Format::parse`'s contract is unchanged from ADR-008.

## Reproduce

```bash
conformance/fetch.sh && cargo xtask conformance-report --write && git diff --stat
```
